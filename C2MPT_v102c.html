省譯說明

省譯標示用於白話翻譯中保留但標記為可省略的詞彙，通常是文言中的虛詞在現代漢語中可省略的情況。

例：「而」→「〈而〉」表示連詞在白話中可省略

文意說明

當詞彙的字面翻譯（詞義）不足以理解句意時，需要補充語境義（文意）來幫助理解。文意顯示在第三行，位於對應的白話詞彙下方。

Line 1: 文言（Classical）
Line 2: 對譯（Modern/Lexical）
Line 3: 文意（Contextual Meaning）
例：「為」→「做」(詞義) →「變為」(文意)

範圍式文意：當多個詞彙共同構成一個文意時，會以範圍方式標記。第一個詞彙下方顯示完整文意，後續詞彙以斜線連接表示屬於同一範圍。

例：「治生商賈」→「尋找維持生活的方法」+「做生意」

語序倒置說明

語序倒置標示用於文言與白話之間詞序不同的情況。使用〔〕括號標記白話翻譯中需要調整位置的詞彙，並以不同顏色區分不同的倒置組。

例：「取之於藍」→「〔從藍草〕取得它」（介詞結構前置）

重構說明

重構標示用於文言結構需要在白話中進行句法重組的情況。當文言的詞彙組合無法直接對應到白話時，需要重新構建句子結構。使用｛｝括號標記重構範圍。

Stage 1: 重構 - 擴展文言結構為白話結構
Stage 2: 倒置 - 在重構範圍內調整語序（如有需要）
例：「仁者安仁」→「仁德的人｛〔在仁德中〕感到安心｝」

通假說明

通假字是指在文言文中，借用同音或音近的字來代替本字的現象。這種現象在古籍中很常見，學習者需要識別通假字才能正確理解文意。

例：「有」→「「又」」表示「有」是「又」的通假字

古今字說明

古今字是指一個字的字形隨時代演變，古代使用的字形（古字）與後來新造或改用的字形（今字）不同。在閱讀古籍時，需要用今字來理解古字的意義。

例：「暴」→「『曬乾』」表示「暴」是「曝」的古字，意為曬乾

詞典格式說明 Dictionary Format

用途：「下載詞典」按鈕會依目前的查詢方向（文言→白話 或 白話→文言）與篇章篩選（全部或單一篇章）匯出一份 CSV 詞典。此格式即為外置詞典的標準格式。

整體：UTF-8（含 BOM）逗號分隔檔，沒有註解列，第一列為標題列，其後為資料列。

欄位（10 欄）：

① classical：文言詞。
② modern：對應的白話譯詞。重構（x）以整個框架的白話串呈現、增譯（+）以整個範圍呈現，不連續者以 ... 分隔。
③ alt：該白話詞的其他可接受譯法（學習模式中視為滿分）；多個以分號分隔，如 有道德的人; 有學問道德的人；無則留空。
④ senseID：同一 classical 下的義項編號（由 1 起算，依頻次排序）。
⑤ example：該義項在語料中的第一個句例，以「文言原句 → 白話翻譯」呈現。
⑥ source：該例句所屬的語料（作者《篇名》＋句子 id）。
⑦ symbol：對齊類型的原始代碼，可組合，如 "" 自然、- 省譯、+ 增譯、# 文意、^ 倒置、x 重構、~ 通假、* 古今字。
⑧ type：類型代碼的中文標籤（如「自然」「省譯＋文意」）。
⑨ frequency：該義項在所選範圍內出現的次數（頻次）。
⑩ editor：此詞典的 id（用以區分多份外置詞典）。

雙向：已移除 方向 欄；因同時有 classical 與 modern 兩欄，可直接雙向解讀。

排序：資料列先按來源詞的總頻次由高至低排列，同一來源詞下再按義項頻次排列。

備註：標點不會收錄為詞條；同一 classical 可有多個義項（多列），每個義項再按對應類型區分。

數據格式說明 Data Format

整體結構：外部檔案為嚴格 JSON，最外層是一個物件，含兩個鍵："chapters"（篇章陣列）與 "sentencesByChapter"（以篇章 id 為鍵的句子集合）。

{ "chapters": [ ... ], "sentencesByChapter": { "篇章id": [ 句子, ... ] } }

篇章 chapter 物件：{ "id": "篇章id", "name": "篇名", "book": "書名", "chapter": "章節", "author": "作者", "era": "時代" }。id 必須與 sentencesByChapter 的鍵相同。

句子 sentence 物件：{ "id": "句子id", "classical": ["詞", ...], "modern": ["詞", ...], "alignments": [ ... ], "parsing": "整句語譯", "comment": "教學說明" }。classical／modern 為已切分的詞陣列（標點亦各佔一格，索引由 0 起算）；parsing、comment 可為空字串。

對齊 alignment：每條為 [cIdx, mIdx, "類型", meta?]。cIdx＝文言詞索引、mIdx＝白話詞索引；第四項 meta 可選。

類型代碼（可組合，如 "+#"、"-^"、"^x"、"x-#"）："" 自然、"-" 省譯、"+" 增譯、"#" 文意、"^" 倒置、"x" 重構、"~" 通假、"*" 古今字。

cIdx 特殊寫法（增譯錨點，以字串標示插入位置）："<3"＝插入於 c-3 之前、"3>"＝插入於 c-3 之後、"2,3"＝插入於 c-2 與 c-3 之間（"<<3" 等為多重錨點變體）。

mIdx 特殊寫法（間接對齊）：當 mIdx 為字串（如 "3"）時，表示重構中由文言詞間接帶出的白話詞位。

meta 物件鍵："scope": 數字 ／ "scopes": 數字陣列（增譯範圍）；"group": 數字（倒置組）；"frame": 數字（重構框架）；"note": 文意內容——可為 "字串"（獨立文意）、數字 n（屬第 n 組文意但本身無內容）、或 [n, "字串"]（第 n 組文意的核心及其內容）。

製作方式：對齊數據十分技術性，不宜手動編寫，應使用配套的「對齊工具（Aligner）」以拖曳方式產生（詳見「說明」區）。本平台只負責呈現，Aligner 負責製作。

載入規則：所有鍵名與字串值必須使用雙引號，不可有註解或尾隨逗號。「取代數據」會清空現有數據後載入；「追加數據」會接續加入（重複篇章 id 會被略過）。

詞典管理 External Dictionary Management

用途：匯入外置詞典（CSV）後，可在「對譯」區的學習模式中，當「提供選擇」開啟時再開啟「外在詞典」，把外置詞典的對應詞加入下拉選項，作知識遷移練習（以舊篇章所學的詞彙，學習新篇章）。

使用說明 User Guide

一、平台簡介

「文白對譯平台」（CTMPT，Classical-to-Modern Parallel Translation）是一個基於「文白對譯」理論框架的文言文閱讀教學平台，由香港大學林葦葉、巢偉儀設計，源自歷時十二年的研究項目《對譯—文言作品的教學策略》。

平台透過詞層對齊（word-for-word alignment），把文言原文與白話翻譯逐詞並列，並以視覺符號標示兩者之間有限而系統的差異，幫助學習者建立「文言只是另一種風格的中文」的自我效能感。

平台共設六大功能區：對譯、數據、詞典、索引、統計、說明，分別對應精讀、資料管理、雙向查詢、詞彙索引、量化分析與操作指引。

二、理論基礎

學理淵源：王寧先生的「嚴格對譯」說

本平台的「對譯」框架，直接植根於北京師範大學王寧先生的訓詁學理論。早在二十多年前，王寧先生在討論中學語文課本文言注釋時，已明確區分兩種性質截然不同的注釋：語義注釋與文意注釋。本平台正是把這一區分，發展為一套具體、可操作、可程序化的文言翻譯方法。

語義注釋＝嚴格對譯（本平台的「詞義／對譯」）

王寧先生指出，語義注釋的任務，是尋求現代漢語與古代漢語之間的「對當關係」，因而往往就是古今漢語之間的「嚴格對譯」——為被釋的文言詞句，找出讀者能夠理解、又能準確對當的現代漢語詞語。這類注釋之所以重要，是因為它能直接成為學生積累詞彙與句法語料的庫存：句子的語義注釋「不但要求構成句子的每個詞都有準確的對譯，而且還要求得句法上的相應」，因此「不但可以積累詞義，而且可以積累句式」。本平台第一至二行（文言／對譯）以及八種對應類型的設計，正是這一理念的視覺化與操作化。

文意注釋＝補充文意（本平台的「文意」第三行）

王寧先生同時提醒：文意注釋陳述的是詞句在特定文章中的內在、語境含義，它「不能離開具體的文章而挪用到別的地方」。她特別強調，指導閱讀時「應非常明確地把這種注釋與語義注釋區分開來，以免讀者產生誤會，錯把對文意的闡發當成詞義的詮釋」。本平台嚴格區分第二行詞義（對譯）與第三行文意，並僅在字面對譯不足以理解時才補充文意，正是為了落實這一告誡。

參考文獻：王寧《訓詁學原理》（北京：中國國際廣播出版社，1996）。本平台在王寧先生「語義注釋／文意注釋」與「嚴格對譯」說的基礎上，發展出文白詞層對齊與八類有限差異的具體教學方法。

文白一貫原理（Consistency Principle）

與將文言視為「陌生外語」的主流觀點不同，本平台主張文言與白話在詞彙和句法上具有高度的系統性一致。大部分文言詞都能與白話詞一一對當、順序一致。過度強調差異會違反語言習得原理，削弱學習者的自我效能感。

有限差異原則（Bounded Difference Principle）

文白差異雖然存在，但在類型上是封閉且有限的。本平台將所有差異嚴格歸納為八類。學習目標因此明確可達——不是無盡地背記「特殊用法」，而是掌握這有限的幾種系統性差異。

對譯的操作程序：六個步驟

在「文白一貫、有限差異」的理論基礎上，本平台把「嚴格對譯」落實為一套可操作、可程序化的六步方法。教師與學生只要依序執行，即可產生忠實而一致的對譯。值得注意的是：這六個步驟其實正好對應處理六類文白差異——方法一（分詞）處理用字差異（通假字、古今字），方法二（詞詞落實）處理省譯，方法三（不增字為訓）處理增譯，方法四（字詞意義）處理文意，方法五（語序一致）處理倒置，方法六（結構一致）處理重構。

方法一：分詞對應：通假字、古今字

先把文言句子切分為一個個有意義的詞（單音節或多音節），作為對譯的基本單位。注意經分詞後的字詞是否有異文、誤字（包括衍字或脫文）、同形字、通假字、古今字。

方法二：詞詞落實對應：省譯

對譯每一個詞——每一個詞都有意義或功能，一個也不能少。只用淺易的白話詞句對譯，不用難詞去譯難詞。除非某文言詞彙一直沿用到今天的白話（字形、詞義不變），否則都必須對譯；尤其文化詞彙，可用詞組對譯。
對譯時，同一義項只用獨一的白話詞彙對譯。對譯句子的工夫，常常體現在對譯虛詞之中。

方法三：不增字為訓對應：增譯

除非文言確有省略，否則絕不增字為訓，以免輕率附會自己的觀點、過度詮釋。只在白話確實需要時，才作有限增譯（如補回承上下文省略的主語、賓語、數量詞等）。

方法四：字詞意義，而非上下文意對應：文意

對譯只求字詞本身的意義，而非整句的上下文意。除非字詞意義與上下文意距離太大，以致對譯出來的句子無法理解，才在第三行另補文意。

方法五：語序一致對應：語序倒置

應盡最大可能保持文白語序一致；除非某一句構的文言語序確實與白話不同，才作語序調整。

方法六：結構一致對應：重構

應盡最大可能保持文白結構一致；除非某一句構的結構確實與白話不同，才作例如句構或活用的調整。

三、三行平行顯示

每個句例以多行對齊方式呈現，清晰區分「詞義」（字面義）與「文意」（語境義）：

行名稱內容
第 1 行文言文言原文，逐詞排列
第 2 行對譯逐詞字面翻譯（詞義 / lexical meaning）
第 3 行文意需要時補充的語境義（contextual meaning），以 # 標示
句譯句譯整句的流暢翻譯（可於設定中開啟「顯示句譯」）

四、八種對應類型

本平台的核心理念是：今天不少學生、甚至教師，都過度強調文言與白話的差異，把文言視為「另一種陌生的語言」。這種取向其實有害——它誇大了文言的難度，違反語言習得的基本原理，並嚴重削弱學習者的自我效能感（self-efficacy）。

事實上，文言與白話在詞彙與句法上高度一致。正是在這片「一貫」的底色之上，文白之間有限的差異才能被「前景化」（foregrounded）而變得可注意；也正因為差異的類型是封閉、有邊界（bounded）的，文言才真正變得可學、可教（learnable & teachable）。本平台的八種對應類型，正是把「以一貫為主、差異有限」這一關係視覺化：第一類體現一貫，其餘七類窮盡差異。

（甲）文白一貫原理 Consistency Principle

絕大部分文言詞都能與白話詞一一對當、順序一致，無需任何特殊處理。這是文言可讀的基礎，也是平台預設展示、份量最重的一類。

① 自然對應 Natural（"　"）

文言詞與白話詞一一對當、語序一致，無需任何調整。這是文白一貫的核心證據，亦是平台預設展示的狀態。

（乙）有限差異原則 Bounded Difference Principle

文白差異雖然存在，但類型封閉而有限，可窮盡歸納為以下七類。透過專屬括號與色彩編碼的「輸入增強」（input enhancement），這些原本不易察覺的差異變得可注意、可辨識。學習目標因此明確可達——不是無盡地背記「特殊用法」，而是掌握這七種系統性差異。

② 省譯 Ellipsis（〈　〉）

文言中的虛詞在白話中可省略。例：結構助詞「之」（如「人之無惑」）在白話中往往沒有對應用法，可標示為省譯。

③ 增譯 Addition（（　））

白話需要補充文言原文沒有明確表達的詞彙，但不增字為訓，僅限有限增譯，如補充承上下文省略的主賓語、數量詞等。例：「宋人有耕者」→補「一個」。增譯錨點以 3,4、7>、<9 等標記，表示插入位置。

④ 文意 Contextual Meaning（#　#）

當詞彙的字面翻譯（詞義）不足以理解句意時，於第三行補充語境義。例：「水為之」的「為」字面是「做」，文意為「變做」。多個詞彙可共構一個文意（範圍式文意）。

⑤ 語序倒置 Reorder（〔　〕）

文言與白話的詞序不同。例：「取之於藍」→「〔從藍草〕取得它」。不同倒置組以顏色 A／B 區分。注意：文言這種語序是最正常的結構，不應視為「倒裝」。

⑥ 重構 Reconstruction（｛　｝）

文言結構需要在白話中進行句法重組，如使動、意動、為動等活用。例：「恥師焉」→「認為｛以人為師｝羞恥」。重構可分兩階段：先擴展結構，再（如需要）於範圍內調整語序。

⑦ 通假 Phonetic Loan（「　」）

借用同音或音近的字代替本字。例：「雖有槁暴」的「有」是「又」的通假字。

⑧ 古今字 Derivate Character（『　』）

古代字形（古字）與後來新造或改用的字形（今字）不同。例：「暴」是「曝」的古字，意為曬乾。

五、設定面板

對譯區頂部的設定面板分為三組開關——標示、互動、模式，可按教學進度逐一聚焦，避免認知超載：

標示（差異類型開關）

七個獨立開關分別開啟各差異類型的結構高亮：省譯、增譯、補充文意、語序倒置、重構、通假、古今字。開啟某一開關時，下方圖例會展開相應的詳細說明。建議一次只開啟一種，集中講解。

互動

  • 多重高亮：開啟後可同時點選並固定多個詞彙作比較（見第六節）。
  • 顯示文言：可隱藏文言原文，用於默寫練習；隱藏時懸停或點擊仍會臨時顯示。
  • 顯示白話：可隱藏白話對譯，用於翻譯練習。
  • 顯示文意：開關第三行的文意補充。
  • 顯示句譯：開關整句的流暢翻譯（預設關閉）。
  • 提示：在句子資訊區顯示該句包含的對譯策略類型提示。
  • 顯示說明：顯示該句的教學說明／按語（預設關閉）。

模式

  • 開發：顯示文言（c-）與白話（m-）的詞序編號，以及增譯錨點、∅ 佔位符等技術標記，方便追蹤對齊關係與講解結構。
  • 學習：把展示式的「對譯」轉為學習者填寫練習，並於設定面板下方展開「學習面板」（詳見第八節）。

六、互動高亮操作

平台提供四種高亮方式，幫助理解詞彙對應關係：

1. 懸停高亮（Hover）

滑鼠移至任一詞彙，即高亮該詞及其完整詞義對應；移開即取消。適合快速預覽。

2. 單一點擊高亮（Single Click）

點擊詞彙可固定高亮。點擊其他詞彙時前一個會自動取消，畫面始終只有一個高亮，適合專注觀察。

3. 多重點擊高亮（Multiple Click）

開啟「多重高亮」後，可同時固定多個詞彙進行比較；再次點擊已高亮的詞可取消。適合課堂討論。

4. 按鈕高亮（Button）

透過「標示」區的七個開關開啟，顯示整個語法結構（如整個重構框架、整個倒置組），而非單一詞彙。

詞義高亮 vs 結構高亮

詞義高亮（懸停／點擊）：顯示一個文言詞對應的所有白話詞。
結構高亮（按鈕）：顯示整個語法結構的所有成員。

七、對譯區功能

  • 篇章／句子選擇：先選篇章，再選句子；可跨篇章。
  • 篩選：在篩選框輸入關鍵字，按文言或白話內容過濾句子。
  • 類型過濾：以下拉選單只顯示含某種對應類型的句子。
  • 導航與跳轉：以上一句／下一句按鈕瀏覽，或於 # 框輸入句號後按 Enter 直接跳轉。
  • 多句並排比較：點擊 ＋ 新增句例，可同時開啟多個句子並行比較；點擊 − 移除。
  • 匯出：以 CSV 或 PDF 按鈕匯出整個篇章的對譯。匯出內容會依當前的可見性設定（文言／白話／文意／句譯／說明／提示）決定顯示或留空，方便製作默寫或翻譯練習工作紙。

八、學習模式

學習模式把「對譯」區由專家展示切換為學習者練習。在「模式」組開啟「學習」開關後，設定面板下方會出現「學習面板」，而每個可測的白話詞會變成輸入格，讓學習者自行填寫對譯（標點不計）。

基本運作

開啟學習模式時，平台會自動把顯示文言設為開（作為題幹）、顯示白話設為關（隱藏參考答案），並關閉文意與說明。此時「顯示白話」即化身為解答鍵：開啟即顯示黃金參考答案並標示對錯，關閉則再次隱藏。學習者的答案會逐句保存，離開該句再返回時不會遺失。

批改與信度

按「批改 Check」會累計評改所有曾到訪的句子（不限於目前畫面），並以顏色標示每格：

  • 綠（正確）：與黃金答案完全相同，或屬該詞的可接受變體（alt，見下），均給滿分。
  • 橙（可接受）：雖非該句答案，但屬同一文言詞在語料庫中其他語境的對譯。
  • 紅（錯誤）：未能對應。
  • 灰（未答）：留空。

批改結果除分數外，會以評分者間信度呈現（專家＝黃金標準／評分者甲，學習者＝評分者乙）：原始一致度 Pₒ（嚴格／含可接受）、期望偶然一致度 Pₑ，以及 Cohen's κ（卡帕係數），量化學習者與專家答案的一致程度。「重設 Reset」會清除全部答案與紀錄。

動態提示

預設情況下，學習模式會關閉懸停／點擊高亮，以免洩漏結構。開啟動態提示後，可恢復一般的懸停與點擊高亮（配合「多重高亮」可同時固定多個）；此高亮只揭示語法結構（如倒置組、重構框架），不會顯示答案。

提供選擇（知識遷移的核心）

開啟提供選擇後，每個輸入格會變成可輸入的下拉選單，列出該文言詞可能的白話對譯候選。候選來源由以下四個獨立開關控制（只在「提供選擇」開啟時出現）：

  • 焦點字詞（預設關）：把該句的黃金答案本身也加入選項，難度最低。
  • 本文（預設關）：加入同一篇章中該文言詞於其他位置的對譯（向本文學習）。
  • 互文（預設開）：加入其他所有篇章中該文言詞的對譯——這正是文白對譯「知識遷移」的核心：以舊篇章累積的詞彙，推敲新篇章。
  • 外置詞典（預設關，須先於「數據→詞典管理」匯入外置詞典方可開啟）：把匯入詞典中該文言詞的對應詞加入選項。

可接受變體（alt）

對齊數據可為某白話詞標記其他可接受的對譯（alt）。學習模式中，凡答中 alt（包括外置詞典所載的 alt），一律以滿分（綠）計算，使評分更貼近真實的教學判斷。

九、數據區與對齊工具（Aligner）

本平台只負責呈現（representation）對齊數據，數據本身則由配套的「對齊工具（Aligner）」製作（production）。兩者分工合作：Aligner 是生產線，平台是展示廳。

對齊工具 Aligner

對齊數據十分技術性，幾乎無法手動編寫。Aligner 提供圖形化介面：編者只需貼上文言原文與白話翻譯（以空行分隔不同句組，每組為「文言行／白話行／可選句譯行」），再以拖曳方式把文言詞與白話詞連結成對。主要操作包括：

  • 跨層拖曳詞語建立對應；按住 Shift 可作一對一重覆連結，按住 Ctrl 可建立「合併連結」（一對多範圍，並強制以逗號字串如 "0,1,2" 輸出多方）。雙擊連線可刪除，雙擊詞語可刪除其全部連結。
  • 為每條對齊標記類型（自然／省譯／增譯／文意／倒置／重構／通假／古今字），並設定 scope、group、frame、note 等參數。
  • 填寫該句的 parsing（句譯）與 comment（說明）。
  • 編輯篇章資料（id／name／book／chapter／author／era），輸出即時更新。
  • 可儲存／載入專案（保留文本、設定、對齊與目前句組），並匯出符合本平台格式的 JSON 數據檔。

Aligner 產生的 JSON，即可在本平台的數據區載入呈現。

數據區 Data Module

數據區用於載入與管理由 Aligner 產生的語料：

  • 載入模式：「取代」會清空現有數據後載入；「追加」會加到現有數據之後（重複篇章 id 會被略過）。
  • 三種載入方式：載入內建範例、載入外部檔案（.json）、載入網絡數據（輸入網址）。
  • 手動編輯：可直接於「篇章數據」與「句子數據」文字框檢視或微調 JSON，按「套用數據」生效。

外部檔案為包含 "chapters" 與 "sentencesByChapter" 的嚴格 JSON 物件；所有鍵名須用雙引號，不可有註解或尾隨逗號。完整欄位與對齊格式，見數據區內的「數據格式說明」。

詞典管理 External Dictionary

數據區設有兩個子頁：數據管理（載入語料）與詞典管理（匯入外置詞典）。外置詞典為 CSV 檔，欄位為 classical, modern, alt, senseID, example, source, symbol, type, frequency, editor（標題以關鍵字辨識，順序不拘；# 起始的註解列會被略過）。其中核心必要欄位只有 classical 與 modern；alt 為其他可接受的白話對譯（多個以分號分隔），匯入後可於學習模式作滿分接受；editor 為詞典 id，用以區分多份外置詞典。

此 CSV 即「詞典」區「下載詞典」所匯出的標準格式。匯入後，於對譯區的學習模式開啟「提供選擇」，再開啟「外置詞典」，即可把外置詞典的對應詞加入下拉選項，進行知識遷移練習。驗證規則：classical 或 modern 只要有任何一格空白即拒絕整份匯入；editor 空白會自動以檔名給予 id，senseID 空白會自動補序。

十、詞典區

提供文白雙向查詢：

  • 查詢方向：文言→白話，或白話→文言。
  • 篇章篩選：可只查詢某一篇章，或全部篇章。
  • 查詢選項：精確匹配、顯示句例。
  • 結果結構：每個詞按義項分組，再依對應類型（自然、省譯、增譯等）歸類，並列出所有出現的句例。點擊句例可直接跳轉至對譯區該句。
  • 快速瀏覽：以頻次列出常見文言／白話詞彙，點擊即查詢。
  • 下載詞典（CSV）：依目前的查詢方向與篇章篩選匯出詞典，欄位包含 classical, modern, alt, senseID, example, source, symbol, type, frequency, editor。此檔即外置詞典的標準格式，可供「數據→詞典管理」重新匯入，用於學習模式的知識遷移。

十一、索引區

以可排序的表格呈現完整的雙向詞彙索引：

  • 索引方向與類型篩選：切換文白方向，並按對應類型過濾。
  • 頻次與百分比：每個詞顯示義項數、總次數，以及在八種類型中各自的次數與百分比。
  • 多重排序：點擊欄標題即可排序（再點一次切換升／降序）；按住 Shift 點擊則可加入多層排序（標題上的數字代表優先次序）。按「清除」可移除全部排序。
  • 匯出：可下載索引為 CSV。

以「結構」為單位的索引（段式索引）

詞典區以單一詞彙為單位（方便逐詞查義、積累詞彙）；索引區則改以結構為單位，更貼合各對應類型的語法本質。具體而言：

  • 增譯（+）／文意（#）／倒置（^）／重構（x）：以整個結構為一個索引條目，而非拆成零碎的單詞。增譯按 scope 範圍（共用詞位的範圍會合併）、文意按 note 組（set-id）、倒置按 group 組、重構按 frame 框架，各自歸併為一條。例如「取之於藍 → 從藍草取得它」的倒置，文言段為「於 藍」、白話段為「從 藍草」，整段並列為一條。
  • 自然（""）／省譯（-）／通假（~）／古今字（*）：仍以單詞為單位（其性質本來就是逐詞對應）。

段內逐詞連結（Token Links）

雖然索引以結構為條目，但每個結構段內的每一個原始詞仍是獨立可點擊的連結。點擊段中任一詞（如「藍草」或「於」），即會帶該詞跳至詞典區查詢其詞義，並自動切換到對應的查詢方向（文言詞查文言→白話，白話詞查白話→文言）。這一設計同時兼顧兩端：索引條目保留結構整體的呈現，而學習者仍能就結構中的每一個詞逐一查義，貫徹「累積文言詞彙是學習文言的必要基礎」這一核心理念。

十二、統計區

統計區量化整個語料庫的「文白一貫」程度，為「有限差異」主張提供實證支持：

  • 語料庫概覽：篇章數、句子數、文言／白話詞彙的種類與總數。
  • 對譯類型統計：各差異類型在句子、文言詞、白話詞層面的分布與百分比；增譯另以「增譯事件／增譯錨點」分開報告。
  • 詞形關係分析：分析每對（文言詞→白話詞）的字形關係，分為保留、擴展、語素保留、替換四類，並計算「嚴格一貫率」與「寬鬆一貫率」。
  • 高頻詞彙與下載：列出高頻文言／白話詞，並可下載全部詞彙為 CSV。

1. Introduction

The Classical-to-Modern Parallel Translation platform (CTMPT) is a reading-instruction tool for Classical Chinese (文言), built on the "文白對譯" (Classical-to-Modern Parallel Translation) theoretical framework. It was designed by LAM Wai Ip and CHOU Wai Yi of The University of Hong Kong, drawing on a twelve-year research project, 對譯—文言作品的教學策略.

The platform uses word-for-word alignment to place the Classical text and its modern translation side by side, marking their limited and systematic differences with visual symbols. This helps learners build the self-efficacy belief that "Classical Chinese is simply another register of Chinese."

It offers six modules: Translation (對譯), Data (數據), Dictionary (詞典), Index (索引), Statistics (統計), and Help (說明) — covering close reading, data management, bidirectional lookup, token indexing, quantitative analysis, and guidance.

2. Theoretical Foundation

Scholarly Origin: WANG Ning's notion of "Strict Correspondence"

The platform's "parallel translation" (對譯) framework is rooted directly in the exegetical theory (訓詁學) of Professor WANG Ning (王寧) of Beijing Normal University. More than two decades ago, in discussing the annotation of Classical Chinese in secondary-school textbooks, WANG drew a sharp distinction between two fundamentally different kinds of notes: semantic annotation (語義注釋) and contextual annotation (文意注釋). This platform develops that distinction into a concrete, operational, and procedural methodology for translating Classical Chinese.

Semantic annotation = Strict Correspondence (our "lexical meaning / 對譯")

WANG argues that the task of semantic annotation is to seek the "correspondence relation" (對當關係) between Modern and Classical Chinese, and is therefore essentially a "strict word-for-word correspondence" (嚴格對譯) — finding, for the glossed Classical word or phrase, a Modern Chinese equivalent that learners can understand and that maps precisely onto it. Such notes matter because they become a learner's stockpile of accumulated vocabulary and syntactic data: the semantic annotation of a sentence "requires not only that every constituent word have an accurate correspondence, but also that the syntax correspond," so it "accumulates not only word meanings but also sentence patterns." The platform's Lines 1–2 (Classical / Lexical translation) and the eight correspondence types are precisely the visualization and operationalization of this idea.

Contextual annotation = Contextual Meaning (our Line-3 "文意")

WANG also cautions that contextual annotation states the internal, context-bound meaning of a word or phrase within a particular text, and therefore "cannot be detached from the specific text and transplanted elsewhere." She stresses that, in guiding reading, one "must very clearly distinguish this kind of note from semantic annotation, lest readers mistake an exposition of contextual meaning for a definition of the word's meaning." The platform's strict separation of Line 2 (lexical meaning / 對譯) from Line 3 (contextual meaning / 文意) — supplying contextual meaning only when the literal correspondence is insufficient — directly implements this warning.

Reference: WANG Ning, Principles of Exegesis (《訓詁學原理》), Beijing: China International Broadcasting Press, 1996. Building on WANG's distinction between semantic and contextual annotation and her notion of "strict correspondence," this platform develops a concrete pedagogy of word-level Classical–Modern alignment and eight bounded difference types.

Consistency Principle (文白一貫原理)

Contrary to the mainstream view that treats Classical Chinese as a "foreign language," the platform argues that Classical and Modern Chinese are highly consistent in vocabulary and syntax. Most Classical tokens map one-to-one onto Modern tokens in the same order. Over-emphasizing differences violates principles of language acquisition and undermines learner self-efficacy.

Bounded Difference Principle (有限差異原則)

Although differences exist, they are closed and finite in type. The platform rigorously reduces all differences to eight categories. The learning goal therefore becomes clear and attainable — not endless memorization of "special usages," but mastery of these few systematic differences.

The Parallel-Translation Procedure: Six Steps

On the foundation of "consistency-first, bounded-difference," the platform operationalizes "strict correspondence" into a concrete, procedural six-step method. Teachers and students who follow it in order can produce a faithful and consistent parallel translation. Notably, these six steps correspond exactly to handling six types of Classical–Modern difference — Step 1 (segmentation) handles graphic differences (phonetic loans, derivate characters), Step 2 (word-for-word fidelity) handles ellipsis, Step 3 (no added words) handles addition, Step 4 (lexical meaning) handles contextual meaning, Step 5 (consistent word order) handles reorder, and Step 6 (consistent structure) handles reconstruction.

Step 1 — Segmentation (分詞)Maps to: Phonetic Loan, Derivate Character

First segment the Classical sentence into individual meaningful words (mono- or multi-syllabic) as the basic units of translation. While doing so, check whether any segmented word involves textual variants, errors (interpolated or missing characters), homographs, phonetic loans, or derivate characters.

Step 2 — Word-for-word fidelity (詞詞落實)Maps to: Ellipsis

Translate every single word — each carries a meaning or function, and not one may be left out. Use only plain, easy modern words; never gloss a hard word with another hard word. Unless a Classical word survives unchanged into today's modern usage (same form and meaning), it must be translated; cultural terms in particular may be rendered with a phrase.
For one and the same sense, use a single, unique modern word. Much of the craft of translating a sentence lies in rendering its function words.

Step 3 — No added words in glossing (不增字為訓)Maps to: Addition

Unless the Classical genuinely omits something, never add words to gloss — this avoids reading one's own views into the text and over-interpreting. Add words only when Modern Chinese truly requires it, and keep such addition limited (e.g. recovering subjects, objects, or measure words omitted from context).

Step 4 — Lexical meaning, not contextual meaning (字詞意義，而非上下文意)Maps to: Contextual Meaning

The translation seeks the lexical meaning of the word itself, not the contextual meaning of the whole sentence. Only when the lexical meaning is so far from the contextual meaning that the translated sentence becomes unintelligible is contextual meaning supplied on Line 3.

Step 5 — Consistent word order (語序一致)Maps to: Reorder

Keep Classical and Modern word order identical as far as possible; make a word-order adjustment only when a construction's Classical order genuinely differs from Modern Chinese.

Step 6 — Consistent structure (結構一致)Maps to: Reconstruction

Keep Classical and Modern structure identical as far as possible; make an adjustment (such as structural rebuilding or flexible/derived usage) only when a construction's structure genuinely differs from Modern Chinese.

4. The Eight Correspondence Types

The platform's central conviction is this: today many students — and even teachers — over-emphasize the differences between Classical and Modern Chinese, treating Classical as "another, alien language." This stance is harmful: it exaggerates the difficulty of Classical Chinese, violates basic principles of language acquisition, and badly undermines learner self-efficacy.

In fact, Classical and Modern Chinese are highly consistent in vocabulary and syntax. It is precisely against this backdrop of consistency that the limited differences can be foregrounded and made noticeable; and precisely because the types of difference are closed and bounded that Classical Chinese becomes genuinely learnable and teachable. The eight correspondence types visualize this "consistency-first, bounded-difference" relationship: the first type embodies consistency, while the remaining seven exhaust the differences.

(A) Consistency Principle

The vast majority of Classical tokens map one-to-one onto Modern tokens in the same order, requiring no special treatment. This is the foundation of readability and the platform's default, weightiest category.

① Natural Correspondence ("　")

Classical and Modern tokens map one-to-one in the same order, requiring no adjustment. This is the core evidence of consistency and the platform's default display state.

(B) Bounded Difference Principle

Although differences exist, their types are closed and finite, exhaustively reduced to the seven categories below. Through "input enhancement" — dedicated brackets and color coding — these otherwise hard-to-notice differences become noticeable and identifiable. The learning goal is therefore clear and attainable: not endless memorization of "special usages," but mastery of these seven systematic differences.

② Ellipsis （〈　〉）

A Classical function word that can be omitted in Modern Chinese. E.g. the structural particle 之 (as in 人之無惑) often has no Modern equivalent and is marked as ellipsis.

③ Addition （（　））

Modern Chinese must supply words not explicitly present in the Classical text — but kept to a minimum (no over-glossing), e.g. recovering omitted subjects/objects or measure words. E.g. 宋人有耕者 → add "一個" (a/one). Addition anchors are marked as 3,4, 7>, <9 to indicate insertion position.

④ Contextual Meaning （#　#）

When the literal (lexical) translation is insufficient, contextual meaning is supplied on Line 3. E.g. 為 in 水為之 literally means "do/make," but contextually "become." Several tokens may jointly form one contextual meaning (range-based paraphrase).

⑤ Reorder （〔　〕）

Word order differs between Classical and Modern. E.g. 取之於藍 → "〔from the indigo plant〕 obtain it." Different reorder groups are distinguished by colors A/B. Note: this Classical order is perfectly normal and should not be called "inversion."

⑥ Reconstruction （｛　｝）

The Classical structure must be syntactically rebuilt in Modern Chinese, e.g. causative, putative, or denominal usages. E.g. 恥師焉 → "consider it shameful ｛to take someone as one's teacher｝." Reconstruction has two stages: first expand the structure, then (if needed) adjust order within the range.

⑦ Phonetic Loan （「　」）

A homophonous or near-homophonous character borrowed for the intended one. E.g. in 雖有槁暴, 有 is a phonetic loan for 又.

⑧ Derivate Character （『　』）

An ancient graph (古字) differs from the later character (今字). E.g. 暴 is the ancient form of 曝, meaning "to sun-dry."

5. Settings Panel

The settings panel at the top of the Translation area has three groups of switches — Markup, Interaction, and Mode — letting teachers focus on one feature at a time to avoid cognitive overload:

Markup (difference-type switches)

Seven independent switches turn on structural highlighting for each type: Ellipsis, Addition, Contextual Meaning, Reorder, Reconstruction, Phonetic Loan, Derivate Character. Turning a switch on expands the corresponding explanation in the legend below. Enabling one at a time is recommended for focused teaching.

Interaction

  • Multi-Highlight: Lets you pin and compare several tokens at once (see Section 6).
  • Show Classical: Hide the Classical text for dictation practice; hidden tokens reappear temporarily on hover/click.
  • Show Modern: Hide the modern translation for translation practice.
  • Show Contextual: Toggle the Line-3 contextual meaning.
  • Show Parsing: Toggle the fluent whole-sentence translation (off by default).
  • Hint: Show, in the sentence-info bar, which translation strategies a sentence contains.
  • Show Comment: Show the teaching note/commentary for the sentence (off by default).

Mode

  • Development: Shows Classical (c-) and Modern (m-) token indices, plus technical markers such as addition anchors and the ∅ placeholder, to help trace alignments and explain structure.
  • Learning: Turns the expert display into a learner fill-in exercise and opens a "Learning Panel" below the settings (see Section 8).

6. Interactive Highlighting

Four highlighting modes help reveal token correspondences:

1. Hover Highlight

Hover over any token to highlight it and its full lexical correspondence; it clears when you move away. Good for quick preview.

2. Single-Click Highlight

Click to pin a highlight. Clicking another token clears the previous one, so only one token is highlighted at a time — ideal for focused observation.

3. Multiple-Click Highlight

With "Multi-Highlight" on, you can pin several tokens simultaneously for comparison; click a highlighted token again to clear it. Useful for class discussion.

4. Button Highlight

Activated via the seven "Markup" switches. It shows an entire grammatical structure (e.g. a whole reconstruction frame or reorder group), not a single token.

Lexical vs Structural Highlighting

Lexical (hover/click): shows all Modern tokens for one Classical token.
Structural (buttons): shows all members of a grammatical structure.

7. Translation Module

  • Chapter/Sentence selection: Choose a chapter, then a sentence; selection can span chapters.
  • Filter: Type a keyword to filter sentences by Classical or Modern content.
  • Type filter: A dropdown shows only sentences containing a given correspondence type.
  • Navigation & jump: Use prev/next buttons, or type a sentence number in the # box and press Enter to jump.
  • Side-by-side comparison: Click ＋ to add example blocks and compare multiple sentences in parallel; click − to remove.
  • Export: Export the whole chapter as CSV or PDF. The export respects the current visibility settings (Classical / Modern / Contextual / Parsing / Comment / Hint), showing or leaving blanks accordingly — convenient for making dictation or translation worksheets.

8. Learning Mode

Learning Mode turns the Translation area from an expert display into a learner exercise. Turning on the "Learning" switch in the "Mode" group reveals a Learning Panel below the settings, and every testable Modern token becomes an input box for the learner to type the translation (punctuation excluded).

Basic behaviour

On entering Learning Mode, the platform automatically sets Show Classical ON (as the prompt), Show Modern OFF (hiding the reference answer), and turns off contextual meaning and comments. Here "Show Modern" becomes the Reveal / answer key: ON shows the gold reference answers and colour-codes them; OFF hides them again. Learner answers are saved per sentence, so navigating away and back does not lose them.

Checking & reliability

Clicking "Check" grades all visited sentences cumulatively (not only the ones on screen), colour-coding each slot:

  • Green (correct): identical to the gold answer, or an acceptable variant (alt, see below) — both awarded full marks.
  • Amber (acceptable): not this sentence's answer, but a rendering of the same Classical token recorded elsewhere in the corpus.
  • Red (incorrect): no correspondence.
  • Grey (unanswered): left blank.

Besides a score, results are reported with inter-rater reliability (expert = gold standard / rater A; learner = rater B): observed agreement Pₒ (strict / inclusive), expected chance agreement Pₑ, and Cohen's κ, quantifying how closely the learner's answers agree with the expert's. "Reset" clears all answers and records.

Dynamic Hint

By default, Learning Mode disables hover/click highlighting to avoid revealing structure. Turning on Dynamic Hint restores normal hover and click highlighting (with "Multi-Highlight," several can be pinned at once); this highlighting reveals only grammatical structure (e.g. reorder groups, reconstruction frames), never the answer.

Provide Choices (the core of knowledge transfer)

Turning on Provide Choices makes each input an editable combobox, offering candidate Modern renderings for that Classical token. The candidates are controlled by four independent switches (shown only when Provide Choices is on):

  • Focal token (default OFF): also include this sentence's gold answer itself — the easiest setting.
  • Same text (default OFF): include renderings of the same Classical token elsewhere in the same chapter (learn from the text itself).
  • Cross text (default ON): include renderings of the same Classical token from all other chapters — the heart of "knowledge transfer": using vocabulary accumulated from earlier texts to work out a new one.
  • External dictionary (default OFF; enabled only after a dictionary is imported under "Data → Dictionary Management"): include the imported dictionary's renderings for that token.

Acceptable variants (alt)

Alignment data can mark additional acceptable translations (alt) for a Modern token. In Learning Mode, any answer matching an alt (including alt from an external dictionary) scores full marks (green), bringing grading closer to genuine teaching judgement.

9. Data Module & the Aligner

The platform only handles the representation of alignment data; the data itself is produced by a companion tool, the Aligner. The two form a division of labour: the Aligner is the production line, the platform is the showroom.

The Aligner

Alignment data is highly technical and practically impossible to hand-write. The Aligner provides a graphical interface: an editor pastes in the Classical text and its modern translation (blocks separated by blank lines; each block is a classical line / modern line / optional parsing line), then links Classical and Modern tokens by dragging them together. Key operations include:

  • Drag tokens across layers to link them; hold Shift for repeated one-to-one multi-links, hold Ctrl for a "combine-link" (one-to-many range, forcing comma-string output such as "0,1,2" on the many side). Double-click a line to delete it; double-click a token to delete all its links.
  • Tag each alignment with a type (natural / ellipsis / addition / contextual meaning / reorder / reconstruction / loan / derivate) and set parameters such as scope, group, frame, and note.
  • Fill in the sentence's parsing (sentence translation) and comment (teaching note).
  • Edit chapter metadata (id / name / book / chapter / author / era); the output updates live.
  • Save/load projects (preserving text, metadata, alignments, and the current sentence pair) and export a JSON data file in this platform's format.

The JSON produced by the Aligner can then be loaded and displayed in this platform's Data module.

Data Module

The Data module loads and manages the corpus produced by the Aligner:

  • Load mode: "Replace" clears existing data before loading; "Append" adds to existing data (duplicate chapter IDs are skipped).
  • Three load methods: load built-in samples, load an external file (.json), or load online data (enter a URL).
  • Manual editing: View or fine-tune the JSON directly in the "Chapters Data" and "Sentences Data" text areas, then click "Apply."

External files are strict JSON objects containing "chapters" and "sentencesByChapter"; all keys must use double quotes, with no comments or trailing commas. For full field and alignment specifications, see "Data Format" inside the Data module.

External Dictionary

The Data module has two sub-tabs: Data Management (loading corpora) and Dictionary Management (importing external dictionaries). An external dictionary is a CSV file with columns classical, modern, alt, senseID, example, source, symbol, type, frequency, editor (headers are matched by keyword, in any order; lines beginning with # are skipped). Only classical and modern are mandatory; alt holds other acceptable Modern renderings (semicolon-separated) that score full marks in Learning Mode, and editor is the dictionary id used to distinguish multiple imported dictionaries.

This is exactly the CSV format produced by "Download Dictionary" in the Dictionary module. Once imported, enable "Provide Choices" then "External dictionary" in the Translation area's Learning Mode to add the dictionary's renderings to the dropdowns for knowledge-transfer practice. Validation: if any classical or modern cell is blank, the whole import is refused; a blank editor is auto-assigned an id from the filename, and a blank senseID is auto-numbered.

10. Dictionary Module

Provides bidirectional lookup:

  • Direction: Classical→Modern or Modern→Classical.
  • Chapter filter: Search within a single chapter, or across all chapters.
  • Options: Exact match, show examples.
  • Result structure: Each token is grouped by sense, then by correspondence type (natural, ellipsis, addition, etc.), listing all occurring examples. Click an example to jump straight to that sentence in the Translation module.
  • Quick Browse: Lists common Classical/Modern tokens by frequency; click to look up.
  • Download Dictionary (CSV): Exports the dictionary for the current direction and chapter filter, with columns classical, modern, alt, senseID, example, source, symbol, type, frequency, editor. This is the standard external-dictionary format and can be re-imported under "Data → Dictionary Management" for knowledge-transfer practice in Learning Mode.

11. Index Module

Presents a complete bidirectional token index in a sortable table:

  • Direction & type filter: Switch direction and filter by correspondence type.
  • Frequency & percentage: Each token shows its sense count, total count, and the count and percentage within each of the eight types.
  • Multi-level sorting: Click a header to sort (click again to toggle asc/desc); hold Shift and click to add extra sort levels (the number badge shows priority). Use "Clear" to remove all sorting.
  • Export: Download the index as CSV.

Structure-based indexing (segment index)

The Dictionary is organized per single word (ideal for looking up word meanings and accumulating vocabulary). The Index, by contrast, is organized per structure, which better reflects the grammatical nature of each correspondence type:

  • Addition (+) / Contextual meaning (#) / Reorder (^) / Reconstruction (x): indexed as whole structures, not split into isolated fragment words. Addition is grouped by scope (overlapping scopes that share a token are merged), contextual meaning by note set-id, reorder by group, and reconstruction by frame — each forming a single index entry. For example, in the reorder 取之於藍 → "obtain it from the indigo plant," the Classical segment 「於 藍」 and the Modern segment 「從 藍草」 are listed together as one entry.
  • Natural ("") / Ellipsis (-) / Phonetic loan (~) / Derivate character (*): remain per single word (these are inherently one-to-one correspondences).

Per-token links within a segment

Although an entry represents a whole structure, each original word inside a segment is still an individually clickable link. Clicking any word in a segment (e.g. 藍草 or 於) sends that single word to the Dictionary for lookup, automatically switching to the appropriate direction (Classical words search Classical→Modern; Modern words search Modern→Classical). This serves both goals at once: the entry preserves the whole structure for display, while learners can still look up every individual word within it — reinforcing the core principle that accumulating Classical vocabulary is the necessary foundation for learning Classical Chinese.

12. Statistics Module

The Statistics module quantifies the overall degree of Classical-Modern consistency, providing empirical support for the Bounded Difference claim:

  • Corpus overview: Number of chapters, sentences, and unique/total Classical and Modern tokens.
  • Type statistics: Distribution and percentages of each difference type at the sentence, Classical-token, and Modern-token levels; Addition is also reported separately as "addition events / addition anchors."
  • Word-Formation analysis: Analyzes the graphic relation of each (Classical→Modern) pair into four categories — Retention, Augmentation, Morpheme Retention, Substitution — and computes "Strict" and "Broad" consistency rates.
  • High-frequency tokens & download: Lists top Classical/Modern tokens and lets you download all tokens as CSV.
